机器坞 · 讨论稿

3 个方案共用一套行为，只换坞的位置和身份的呈现

A 侧栏坞 你的原意

好在
  • 坞属于侧栏，会话列表拿到整列高度；头像 28px，一屏能看 7 台。
  • 机器名贴着坞显示，身份和切换器在同一处，视线不用来回跳。
  • 侧栏收起时坞变成底部浮条，机器切换不丢。
代价
  • 268px 只放得下 5–7 台，再多要横向滚（有渐隐 + hover 箭头）。
  • 坞的视觉重量全压在侧栏底部，侧栏内容很长时容易看不见。

B 全局底栏 把坞升级成一条 dock

好在
  • 坞、计数、当前机器名、添加机器都在同一条 60px 的 shelf 上，切换与总览是同一个动作。
  • 1280px 能平铺 20+ 台，不需要横向滚动；侧栏收起也不用浮坞。
  • 头像 32px，active 头像下面有一个 4px 指示点，像 macOS Dock。
代价
  • 底部多一条常驻 chrome，终端少 60px；和状态栏、卡片下沿的关系要很小心。
  • 侧栏底部的“会话列表 → 坞”的垂直关系被打断，坞变成全窗口的东西。

C 名牌坞 身份优先

好在
  • 每台机器都有名字，不用猜 CM / M2；mac-mini 和 mac-mini-2 不会混。
  • active 头像的名字变亮，身份和切换仍然是同一个控件。
代价
  • 一行只放 4–5 台，坞高 56px；名字截断后还是要 tooltip。
  • 视觉噪音比纯头像大，10 台以上会显得挤。

三案共同规则

  • 每台机器各自记住“打开了哪些标签 / 当前哪个标签”，切回来原样恢复。
  • 顶部标签只属于当前机器 → 标签上不再需要机器名 pill。
  • 切换只做 200ms 淡入，不做横移：横移会让人以为同时在“看”多台机器。
  • 计数默认全舰队；点数字会跨机器跳到下一条对应会话（⌘J 同义）。

还没拍板的

  • 计数口径：全舰队更像收件箱，但头像徽标已经按机器计数；两个口径同时出现会不会重复？顶部可切换看对比。
  • 列表和标签重复：侧栏列出全部会话、顶部列出已打开标签，是两套“同一批东西”。要不要让列表只显示“未打开的会话”？
  • 排序：固定手动顺序（保住肌肉记忆）vs 需要你优先（更快但位置会跳）。我倾向固定 + 徽标。
  • 展开态：点一个未打开的会话，是在当前机器开标签，还是切机器再开？（现在：未打开就开标签，并设为当前。）
  • 折叠后的坞：A/C 浮在底部中间；B 不需要。浮条要不要也显示机器名？
  • 空机器（pi-4）和离线机器（macbook-air）在坞里是否都要占一个位置？我倾向都占，位置稳定。
